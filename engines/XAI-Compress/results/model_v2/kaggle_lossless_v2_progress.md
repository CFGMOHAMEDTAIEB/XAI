# Kaggle Lossless V2 progress

Kernel version 2 ended with `ERROR`. Its one-epoch smoke test passed at validation CE 5.5439666452 (7.9982531858 BPB), but every full-training epoch from 1 through 8 reported non-finite training and validation CE. The scheduler reduced learning rate from 0.001 to 0.0000625 and early stopping fired at counter 8. No best production checkpoint was created because no finite validation result existed.

Classification: `NUMERICAL_INSTABILITY`, followed by a consequential `CHECKPOINT_ERROR` when export attempted to load the absent best checkpoint. This was not OOM: measured peak allocated VRAM stayed below 279 MB on the assigned 15.6 GB Tesla T4.

Kernel version 3 was submitted after moving the attention score/softmax calculation to FP32 while retaining AMP for the rest of training, plus immediate non-finite loss detection. Its latest verified state is `KernelWorkerStatus.RUNNING`. Kaggle's live-log endpoint returned no content, so its stage, assigned hardware, smoke results, and production results are not yet measured. No Version 4 was submitted.

Subsequently exposed Version 3 results show smoke remained finite but production epoch 1 again reported NaN train/validation metrics. This fails the numerical-stability gate. The latest source dataset contains the fail-fast check before backward/aggregation, but the observed epoch-level behavior cannot occur through that code path; Version 3 most likely snapshotted the preceding dataset version during the source upload/version race. A bounded diagnostic mode and reproducer were added locally. No Version 4 has been submitted.

Version 4 used the source snapshot that passed 65,536-sample CUDA AMP diagnostics. Its smoke epoch passed with finite train CE 5.5972910233, validation CE 5.5547426048, and validation BPB 8.0137996093. Guarded production stopped before completing epoch 1 at step 10,169: the first non-finite value was the gradient for `blocks.2.attn.qkv.weight`. The raw forward loss was finite because its pre-backward guard passed; the optimizer step for the failing batch was not executed. Classification: `GRADIENT_INSTABILITY`. Kernel status is `ERROR`; no production best/latest checkpoint was created and no Version 5 was submitted.

Version 5 used GradScaler initial scale 1024 and growth interval 10000. Its smoke epoch passed with finite train CE 5.5944521854, validation CE 5.5564471449 and validation BPB 8.0162587408. Production stopped before completing epoch 1 at the first instrumented non-finite forward activation: layer 3 `residual_ffn`, shape `[16,256,192]`, with finite values already spanning -63937.7148 to 19240.5195. The later exact CUDA reproduction localized the earlier operation: at step 27,671 / 442,736 samples, a finite layer-3 FP16 `ffn_output` maximum of 62,624 overflowed when dropout applied its `1/0.9` training rescale. The FP32-dropout correction removed that specific failure location. Classification: `LEARNING_RATE_DRIVEN_PARAMETER_GROWTH` culminating in an AMP dropout overflow, not a residual double-add.

Version 6 retained the architecture and FP32 attention/dropout safeguards, reduced LR from 0.001 to 0.0005, and passed the one-epoch diagnostic. Production epochs 1--3 were finite, with validation BPB 7.9715660175, 7.9702470172, and 7.9693499410. Layer-3 activation maxima accelerated from 2,371.74 to 3,596.60 to 6,558.25. Epoch 4 stopped at step 24,024 before the failing update; the first non-finite tensor was `gradient:output.weight`. Classification: `MULTI_EPOCH_ACTIVATION_GRADIENT_GROWTH`. LR 0.0005 is rejected, and the one-epoch gate is superseded by a minimum five-complete-epoch gate.

No Version 7 production run has been submitted. The next authorized external action is a non-production five-epoch diagnostic at LR 0.0003, with an LR 0.0002 diagnostic permitted only after a genuine numerical or unsafe-growth failure. Architecture changes remain prohibited until both controlled LR candidates fail or expose genuine residual-growth risk.
